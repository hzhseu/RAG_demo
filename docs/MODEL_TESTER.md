# 独立回答模型测试

双击项目根目录的 `Start-model-test.cmd`，或 `dist/ModelTester/ModelTester.exe`。
启动时校验已有回答模型，随后自动打开本地浏览器页面。保留启动窗口，退出时按 Ctrl+C；只关闭浏览器不会关闭后台。关闭启动程序后，其模型子进程也会退出。

不需要 `.ragkb`、PPT、嵌入模型、OCR 或 LibreOffice。所有界面资源本地提供，程序只加载 `runtime.json` 中的回答模型，以 llama.cpp CPU 模式运行，不会联网下载模型。

## 测试方式

- 自由问答：直接输入问题，测试模型自身能力。
- 根据材料回答：粘贴原文，再输入问题，测试模型是否遵循材料。
- 生成摘要：粘贴文本，填写可选的摘要长度或格式要求。

可点击“填入示例”快速开始。同一会话支持持续对话：模型会收到先前已完成的问答，因此可以追问“请继续解释”“改写成英文”。材料问答和摘要完成后也支持追问，原始材料保留在上下文中。
点击“新建对话”开启独立会话；下方会话列表可切回旧会话继续。已开始的会话固定模式和原始材料，需要更换时新建对话。
输出上限范围为32–4096 tokens，默认768；temperature固定为0.1，与项目的生成默认值一致。
上下文容量和CPU线程数读取所选模型配置，默认8192 tokens和4线程。全部历史、材料、本轮输入和预留输出超过上下文时提示错误，可缩短本轮输入、降低输出上限或新建对话。不会静默裁剪历史或材料。

输出逐步显示，可停止生成。失败或取消的轮次在页面保留，但不会带入后续模型上下文。达到输出上限的回答会标注，可以要求模型继续。
记录包括模型文件名、模型哈希、完整提示词、参数、回答、结束原因和耗时。“导出本轮记录”保存最新一轮JSON；“导出完整对话”保存全部轮次与上下文。最多保留30个会话、每个会话100次测试，仅保存在进程内存，刷新页面可以恢复，退出程序后清除。达到上限时提示新建或导出后删除，不自动丢弃历史。

加载耗时包括启动及等待模型就绪。首字等待和总耗时从提交开始计算，包含模型加载与输入处理。完成后保持模型加载供下次测试复用，因此后续加载耗时接近零。输出token数来自模型服务；若服务未提供则显示“—”。达到输出上限会显示提示，避免把截断的回答误认为完整回答。

停止期间会终止本工具拥有的模型子进程，下次测试重新加载。不会停止其他应用的模型进程。请避免与知识库构建同时进行高负载测试，以免干扰速度比较。

本工具测试同一模型和量化文件的直接输出，使用自己的简短提示词，不复现知识库检索、引用校验或分段摘要流程，因此测试结果不等于完整RAG效果。

## 添加和选择模型

页面右上角的“回答模型”下拉框默认包含原项目的Qwen模型。切换到其他模型会校验其文件并释放原模型，新建一段独立对话；首次发送消息时加载新模型。旧会话保留，点击旧会话会切回该会话绑定的模型。生成期间不能切换会话或模型。

后续添加本地模型无需修改程序代码：

1. 准备与所用llama.cpp兼容、含聊天模板的文本生成GGUF模型。
2. 将`model-test-models.example.json`复制为`model-test-models.json`，放在`ModelTester.exe`旁。源码运行时可放在项目根目录。
3. 修改示例中的`id`、显示名称`name`、模型`path`和真实`sha256`。全零哈希只是占位值，不能用于真实模型。可在`models`数组中添加多项，`id`不能重复，也不能使用保留值`default`。
4. 完全退出测试程序后重新启动，下拉框会列出新模型。

使用PowerShell计算模型哈希：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'D:\models\my-model.gguf'
```

目录中的模型不会被自动下载或扫描。`path`的相对路径以模型列表JSON所在目录为基准。`context`和`threads`可分别设置；如某模型需要新的llama.cpp，可增加`llama_server`字段指定其可执行文件路径。运行时的聊天模板、模型架构兼容性和机器内存仍需实际验证。

也可以通过`--models "D:\配置\model-test-models.json"`显式选择模型列表。默认搜索顺序为EXE所在目录、`runtime.json`所在目录；未发现列表文件时只列出原有模型。

## 打包与迁移

`ModelTester` 是独立启动程序，但复用既有模型文件。复制到其他电脑时保留以下相邻目录：

```text
任意目录/
  ModelTester/
    ModelTester.exe
    _internal/
  NordRAG/
    runtime.json
    runtime/...
```

不需要安装Python。不要只复制EXE。也可以在ModelTester目录放置自己的`runtime.json`，或显式指定配置：

```powershell
.\ModelTester.exe --config "D:\已有程序\runtime.json"
```

配置中的相对路径始终相对于配置文件所在目录。启动只校验回答模型的SHA256，并检查llama-server文件存在；不会执行完整知识库运行组件检查。

源码运行与独立打包：

```powershell
.venv/Scripts/python.exe -m nordrag.model_test
.venv/Scripts/python.exe scripts/package_model_test.py
```

打包脚本不会覆盖已有`dist/ModelTester`目录；重新打包前请先保留旧目录。原知识库程序及交付压缩包不会被此脚本重新打包。
