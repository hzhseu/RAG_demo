# 离线检索重排

新安装默认开启顶部“检索重排”。开启时，系统先执行原有关键词与向量混合检索，
再使用随包提供的 Qwen3-Reranker-0.6B Q8_0 对最多 30 个候选片段评分，
取前 8 个交给现有证据预算处理。重排评分不是答案正确概率，也不用于自动拒答。

## 使用与对照

- 切换开关会创建同问答模式的新会话；生成期间不可切换。
- 会话固定其检索模式。打开历史会话会恢复相应开关；旧会话按原混合检索处理。
- 界面记住本浏览器最近的选择。新建对话、切换模型和知识库会沿用当前选择。
- 知识问答与高级问答均支持重排。全库目录统计及所选文档的全量专题总结不经过重排。
- 回答下方显示实际使用的模式和重排耗时。模型缺失、校验失败、超时或评分异常时，
  明确显示“已使用原混合检索”和原因；原始前 8 条证据保持不变。点击停止会终止本次任务，
  不会以回退方式继续生成。

在目标环境对照时，使用同一知识库、同一回答模型和相同问题，分别开启、关闭重排，
每次建立新会话。记录正确答案是否出现、引用是否支持结论、首条有效证据及等待时间。
跨页比较题需要核对双方证据，而不是仅检查引用编号。多轮问题使用完全相同的提问序列。
没有答案的问题也应纳入人工检查；本次没有新增拒答阈值。

不需要重建已有 `.ragkb`。重排在运行时评分，不改变原文、页码、分块和嵌入向量。
程序运行时不下载模型或访问远程推理服务。

## 配置与部署

`runtime.json` 新增：`reranker_model`、`reranker_model_sha256`、
`reranker_candidates`（30）、`reranker_top_k`（8）、`reranker_threads`（4）、
`reranker_context`（8192）、`reranker_timeout_seconds`（120）。超时覆盖模型验证、加载、
分词和评分；回收进程可能另需短暂清理时间。长输入只截断评分副本，原始引用保留完整内容。

模型为 `ggml-org/Qwen3-Reranker-0.6B-Q8_0-GGUF`，revision
`a02f48bb4f057028298c21fa033da2b30d7742d5`，文件约 639 MB，SHA256：
`22c9979ce4fbcdc5acdc310c6641c32797eff1aa980b8f7a2db8a8ea23429a48`。
使用已有 llama.cpp b11326；不需要新增 Python 推理依赖。模型与许可证包含在完整离线包中。

可运行 `kb-builder.exe doctor` 检查组件。重排组件故障不阻断原混合检索，但完整交付包
必须通过该组件检查。重新打包会保留旧程序目录和已有知识库，不覆盖原知识库文件。

## API 与验证边界

创建会话可传 `retrieval_mode: "rerank" | "hybrid"`，省略时默认 `rerank`。
最终事件和保存的回答包含 `retrieval_mode`、`rerank_seconds`、`rerank_fallback`、
`rerank_reason`。目录统计与专题总结实际模式为 `not_applicable`。
普通日志只保存固定状态与错误码。现有会话导出含原问题、回答和证据，不是脱敏报告。

开发侧真实模型对照入口为 `scripts/validate_reranking.py`，记录在
`docs/validation/reranking-comparison.json`。12 道人工题上，开关两种模式 Recall@8 和
MRR@8 均为 1.0，无排名退化；4 组中英文、数字与历史年份干扰测试通过。
这套小型题集不能证明真实业务准确率提升。首次重排约 5.55 秒，后续平均约 3.87 秒，
仅代表当前开发机与 9 片段样本，30 候选和目标硬件需现场测量。
